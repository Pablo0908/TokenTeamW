## DEPLOY.md  (was in the project root)

````markdown
# Deploying TokenTeamW (Render + Vercel)

Backend → **Render** (Flask API), Frontend → **Vercel** (Vue PWA). Both have free tiers and
sign in with GitHub. The code is already pushed: backend on the **`Backend`** branch, frontend
on the **`frontend`** branch of `github.com/Pablo0908/TokenTeamW`.

Deploy order matters (the frontend needs the backend URL, the backend needs the frontend URL):
**A) backend → B) frontend → C) wire the two URLs together.**

---

## A. Backend on Render

1. Go to **https://render.com** → **Get Started** → **Sign in with GitHub** (authorize it to see the repo).
2. **New +** → **Blueprint**.
3. Pick the **`Pablo0908/TokenTeamW`** repo, and set the branch to **`Backend`**. Render reads `render.yaml` automatically.
4. It will ask for the **secret** env vars (marked `sync: false`). Copy these from your local **`backend/.env`**:
   - `MONGO_URI` → the full Atlas string (the one with the corrected password `…X8Iyl`)
   - `JWT_SECRET` → value from `backend/.env`
   - `SECRET_KEY` → value from `backend/.env`
   - `FRONTEND_URL` → put `https://example.com` for now (we fix it in step C)
   - `CORS_ORIGINS` → leave **blank** for now (fixed in step C)
   - (`DB_NAME`, `FLASK_ENV`, `PYTHON_VERSION` are already filled by the blueprint)
5. **Apply** / **Create**. First build takes a few minutes.
6. When it's live, copy the service URL — it looks like **`https://tokenteamw-api.onrender.com`**.
7. Test it: open `https://<your-render-url>/health` in a browser → you should see `{"status":"ok"}`.

> Atlas access: your cluster is already open to `0.0.0.0/0`, so Render can connect. If you later
> restrict it, add Render's outbound IPs to Atlas Network Access.

---

## B. Frontend on Vercel

1. Go to **https://vercel.com** → **Sign Up** → **Continue with GitHub**.
2. **Add New… → Project** → **Import** the `Pablo0908/TokenTeamW` repo.
3. Configure:
   - **Root Directory:** `frontend`  ← important (the app lives in the `frontend/` subfolder)
   - **Framework Preset:** Vite (auto-detected)
   - Build Command `npm run build` and Output `dist` are the defaults — leave them.
4. **Environment Variables** (add these three):
   | Name | Value |
   |---|---|
   | `VITE_API_URL` | your Render URL from step A6, e.g. `https://tokenteamw-api.onrender.com` |
   | `VITE_USE_MOCK` | `false` |
   | `VITE_PUBLIC_URL` | (leave blank for now; set to your Vercel URL after first deploy) |
5. **Deploy.** When done, Vercel gives you a URL like **`https://token-team-w.vercel.app`** — copy it.
6. After the Production Branch defaults to `main`, change it to **`frontend`**:
   **Project → Settings → Git → Production Branch → `frontend`**, then **redeploy** (Deployments → ⋯ → Redeploy).

---

## C. Wire the two URLs together

Now that you know the Vercel URL, update the **backend** so CORS allows it and QR codes point to it:

1. Render → your service → **Environment**:
   - `FRONTEND_URL` = your Vercel URL (e.g. `https://token-team-w.vercel.app`)
   - `CORS_ORIGINS` = the same Vercel URL
2. **Save changes** → Render redeploys automatically.
3. (Optional) Vercel → set `VITE_PUBLIC_URL` to the Vercel URL and redeploy.

---

## D. Verify (and the camera now works on your phone)

1. Open your **Vercel URL** on your phone — it's HTTPS, so the camera permission prompt now appears.
2. Log in as admin: `admin@lyfter.cc` / `Admin123!`
3. Create an event → add a badge (generates a QR) → the QR encodes the **Vercel** redeem URL.
4. Open the **Scan** screen → allow the camera → scan the badge QR → it redeems.
5. Admin **Users → View progress** shows that user's events and claimed badges.

### Notes
- **Render free tier sleeps** after ~15 min idle; the first request then takes ~50s to wake. The app
  already shows a friendly "server may be starting up" message during that cold start.
- Production runs against the **same MongoDB Atlas** database as local — events/badges you create are shared.
- Mock mode is off in production (`VITE_USE_MOCK=false`), so everything is live data.
````
