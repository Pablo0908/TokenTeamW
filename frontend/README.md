# Lyfter Badge App — Frontend

Mobile-first PWA where attendees scan QR codes to collect event badges and organizers
create events, mint badges, and watch live redemption counts.

**Stack:** Vue 3 (`<script setup>`) · Vue Router · Pinia · Axios · Tailwind CSS · DaisyUI · Vite · `vite-plugin-pwa`

## Getting started

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

The app boots in **demo mode** (`VITE_USE_MOCK=true`) with built-in sample data, so every
screen is fully previewable without the backend. Sign in with any password; use an email
containing `admin` (e.g. `admin@lyfter.cc`) to open the organizer panel.

## Connecting to the real API

1. Copy `.env.example` to `.env` and set:
   ```bash
   VITE_API_URL=http://localhost:5000   # or the Render API origin
   VITE_USE_MOCK=false
   ```
2. The API base URL is read only from `VITE_API_URL` — never hardcoded. The frontend talks
   exclusively to the Flask API, which owns the MongoDB Atlas connection. The client never
   touches MongoDB directly.

```
├── stores/                  auth.js, events.js, badges.js (Pinia, composition)
├── views/                   Login, Register, Home, Scan, Badges, Events,
│   └── admin/               EventDetail, Redeem, Profile, admin/*
└── components/
    ├── ui/                  NavBar, AlertMessage, LoadingSpinner
    └── domain/              BadgeCard, EventCard, ProgressBar, QRDisplay, StatTile, Confetti
```

## PWA

`vite-plugin-pwa` emits the manifest + service worker. Icons (192 / 512 / 512-maskable) are
generated by `scripts/gen-icons.mjs`. Installability is verified against a production build.

## Deploy (Vercel)

Framework preset **Vite**, build `npm run build`, output `dist`. `vercel.json` adds the SPA
history-mode rewrite. Set `VITE_API_URL` (Render origin) and `VITE_USE_MOCK=false` in the
Vercel project env.

## Notes

- QR decoding uses **`qr-scanner`** — `BarcodeDetector` isn't available on iOS Safari, so this
  library is used as a reliable cross-browser engine.
- QR images are rendered from the backend's `qr_url` when present; in demo mode they fall back
  to a public QR image service so the codes are real and scannable.
